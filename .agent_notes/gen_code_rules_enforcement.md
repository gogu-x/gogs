# 代码生成/修改时必须强制遵守的规范（用户明确要求：一定要按此约束）

来源：/data/330gs/gs/.kiro/prompts/gen-code.md

无论是新增功能代码，还是修改/修复现有代码，每次写 Go 代码都必须自查以下 14 条规则：

1. 结构体字段短变量：同一字段在函数内访问超过 2 次，必须声明短变量复用（如 `s := a.GetSomeField()`），禁止重复调用 Getter。
2. if 变量作用域：获取变量后立即判断的场景，直接在 if 语句中声明（`if r := GetXxx(); r != nil {`），缩小变量作用域。
3. case 语句合并换行：多个 case 值相同处理逻辑时，每个 case 值独立一行，与逻辑语句分段书写，不要写成 `case A, B, C:` 一行。
4. Getter 方法访问结构体：字段访问必须用 Get 方法（`a.GetField()`），不能直接访问字段（`a.field`）。Set 方法不做强制要求。
5. 重复代码抽离：发现相似逻辑段必须提取为公共函数/方法，杜绝冗余代码。
6. 初始化函数直接返回：构造函数尽量直接 `return &Struct{...}`，避免先声明变量再逐字段赋值最后返回。
7. 禁止随意穿透访问：结构体嵌套字段访问必须封装访问函数，禁止链式穿透（`rt.GetActionCtx()` 而非 `rt.GetRallyCtx().ActionCtx`）。
8. 参数换行：函数调用实参或函数签名形参超过 3 个必须换行编写。
9. Slice 类型字段 Add 方法：结构体中 slice 字段新增元素必须封装 Add 方法（如 `AddItem`），禁止外部直接 append。
10. 返回值规范：函数返回值能用 errorCode 体现的用 cspb.ErrCode，否则用 bool（true=成功，false=失败），不要用裸 int 表示成功/失败。
11. RallyTroop 变量命名：项目内 RallyTroop 类型变量统一命名为 `rt`。
12. 数据重置封装：需要重置/清空数据结构必须封装 `resetXXX` 函数/方法，禁止在业务逻辑中逐字段置零。
13. 注释完整：每个导出结构体及字段必须有注释。结构体用 `// StructName 描述`，字段用行尾注释 `// 描述`。
14. 关键路径日志：接口入口、数据修改（记录 before/after）、状态变更、条件不满足分支、异常分支、定时触发等关键路径必须加日志。
    格式：`tlog.Infof("[模块名/函数名] 做什么事, key1=%v key2=%v pid=%v", val1, val2, pid)`
    - 前缀 `[模块名/函数名]` 方括号包裹
    - 描述用中文说明当前操作
    - 关键数据用逗号分隔 `key=%v` 格式
    - 涉及玩家操作必须带 `pid=%v`
    - 异常/错误用 `tlog.Errorf`

## 代码生成标记规则（结构体级别）

- 需要持久化到 DB（玩家存档、全局数据）→ 加 `// +deepcopy-gen=true`
- 字段需要在多处被访问 → 加 `//go:generate accessor_engine2 <StructName>` 自动生成 Get/Set 方法
- 纯内存中间结构体（请求参数、临时计算结果）→ 不需要以上两个标记
- 注意：包级别也可以用 `// +deepcopy-gen=package` 声明在 doc.go 顶部，使该包内所有结构体默认生成 deepcopy，此时具体结构体要排除则用 `// +deepcopy-gen=false`

## 执行要求

- 每次生成新代码或修改现有代码后，在给出结果前自行过一遍这 14 条清单，逐条确认是否违反。
- 如果因为兼容现有代码风格必须违反某条规则（比如现有函数已经是裸 int 返回值，新增逻辑要保持接口一致），要明确告知用户这是权衡后的例外，不要静默违反。
- 与 @audit 工具的代码规范检查项（2.6 系列）保持一致，二者共用同一套规则来源。
